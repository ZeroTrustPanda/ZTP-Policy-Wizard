## ZTP Policy Wizard 2.0.0

Proof-of-value automation for Zscaler SEs across **Zscaler Client Connector → Zscaler Internet Access → Zscaler Private Access → Zscaler Digital Experience**, using one set of OneAPI (ZIdentity) client credentials. It implements the *Policy Wizard 2.0 Requirements Specification* and was live-tested end to end on a Zscaler tenant: create, re-run, update and clean up.

### Downloads
| Computer | File |
|---|---|
| **Mac with Apple silicon (M1–M4)** | `ZTP-Wizard-2.0.0-macos-arm64.zip` |
| Windows 10/11 (64-bit) | `ZTP-Wizard-2.0.0-windows-x64.zip` |
| Intel Mac | `ZTP-Wizard-2.0.0-macos-x64.zip` |

Unzip and double-click `ZTP-Wizard`. Your browser opens the wizard at `http://127.0.0.1:3000`; your API credentials stay on your computer and are never written to logs. The builds aren't code-signed yet. On a Mac, right-click → *Open* → *Open* the first time (if macOS still refuses, run `xattr -d com.apple.quarantine ZTP-Wizard`). On Windows, SmartScreen → *More info* → *Run anyway*.

### Highlights
- **One global prefix** names everything the wizard creates. Re-running **updates** objects in place across ZIA, ZCC and ZPA instead of duplicating them.
- **Dry run first, every time:** the preview shows Create / Update / No change for each object, and the server refuses an apply that doesn't match it. ZIA changes are activated automatically.
- **Licensing is read from the tenant:** unlicensed features are greyed out.
- **Summary report** after each run (Markdown and printable HTML), marked sensitive when it holds a ZPA provisioning key.

### Zscaler Internet Access
- **Scope → Baseline Framework → Rules → Dry run → Apply.** Baselines are HIPAA, HITRUST, NIST 800-53, NIST 800-171, PCI DSS, CJIS, SOX, FERPA and GDPR, or Strict / Balanced / Permissive / Zero Trust Hospital.
- **Rule review:** Select all / Deselect all and Allow all / Block all per category and for the whole page, plus Isolate for URL rules. Selections can be saved and loaded.
- **New areas:**
  - Inline DLP Monitor and Block, with custom dictionaries and engines (ICD-10, MBI, MRN and more).
  - Endpoint DLP.
  - Cloud Sandbox Standard and Advanced, with AI Instant Verdict.
  - AI Prompt Capture (14 GenAI apps).
  - UCaaS: Zoom, GoTo, RingCentral, Webex and Talkdesk, always enabled.
  - ATP defaults.
- **Granular Cloud App Control**, showing what URL filtering can't:
  - Google Drive, Dropbox and Box: view-only.
  - Facebook and X: view, no posting.
  - LinkedIn: read-only.
  - ChatGPT, Gemini and Copilot: allowed, no file uploads.
  - Slack: chat, no file uploads.
- **Isolate Miscellaneous / Unknown:** these sites open in Cloud Browser Isolation (Caution if the tenant has no isolation profile).

### Zscaler Client Connector
- Windows and macOS forwarding and app profiles from the POV best-practice templates. Every setting is a switch.
- Predefined IP-based bypass apps are read live, with a checklist directly under the bypass switch.
- VPN Gateway Bypasses, IP Inclusions / Exclusions and DNS Inclusions / Exclusions are validated before anything is sent. IP lists take IPs or CIDRs only.
- ZPA reauthentication is on by default. The forwarding profile has separate IPv6 switches for dual-stack and IPv6-only networks.

### Zscaler Private Access (new)
- **Wizard:** App Connector Group → Provisioning Key (masked, with reveal and copy) → Segment Group → Server Group → Application Segment, with the recommended defaults.
- **CSV bulk upload** of application segments:
  - Columns: Application Name, Destinations, Ports. Put several values in a cell separated by `;`, and write UDP ports as `udp:53`.
  - A template download, per-application settings and row-numbered validation.
  - Each application becomes its own segment.
- **Bulk Manager** removes prefixed objects in dependency order.

### Zscaler Digital Experience
- **Bulk Manager** for prefixed custom apps and collections.

### Fixed during live testing
- ZIA API sessions that end mid-run are renewed automatically.
- One failed rule no longer breaks the rule order for later rules.
- Timed-out reads and updates are retried once.
- Descriptions stay within the 255-byte limit.
- Cloud App Control actions match what ZIA accepts.
- Cloud Sandbox uses only the file types it accepts.
- A domain in a ZCC IP list (which ZCC rejects) is blocked in the dry run.
- ZCC and ZPA re-runs report No change correctly.
- ZPA's subnet + Continuous health check limit is enforced in the dry run.
- The Mobile Admin page could show a render error when the bypass-app list arrived early.
- The first Mac build crashed at start because it tried to create a log folder at the build machine's path.

### Known limitations
- Endpoint DLP rule creation wasn't live-tested, because the test tenant isn't licensed.
- The ZCC and ZDX APIs allow about 100 calls per hour per API client. When that limit is reached, the wizard says to wait rather than hanging.
