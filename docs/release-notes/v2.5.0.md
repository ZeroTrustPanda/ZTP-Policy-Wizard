# ZTP Policy Wizard 2.5.0 — release notes for 2.0 → 2.5.0

Proof-of-value automation for Zscaler SEs. It covers **Zscaler Client Connector → Zscaler Internet Access → Zscaler Private Access → Zscaler Digital Experience**, plus **AI Guard**, using one set of OneAPI (ZIdentity) client credentials. This page brings the 2.0, 2.1, 2.2, 2.3, 2.3.1, 2.4.0 and 2.5.0 releases together. Every release was tested end to end on a live Zscaler tenant: create, re-run, update and clean up.

## What's in 2.x

### AI Guard (new in 2.5)
AI Guard is a separately licensed SKU that needs ZIA. On *Build the POV* it is a fourth toggle: switching AI Guard on switches ZIA on, and ZIA can still run without AI Guard. The AI Guard step comes right after Internet Access, and also has its own page under ZIA.
- **Checks first:**
  - The AI Guard API (`/aiguard/v1`, the "zguard" check) is reachable with the same OneAPI client.
  - Gen AI Security (`ZS_DP_GEN_AI`) is present for prompt capture.
  - Any Proxy Chaining root certificate, AI Guard proxy and proxy gateway already in ZIA.
- **Pick the AI apps:**
  - ChatGPT, Microsoft 365 Copilot, Claude and Gemini are on by default.
  - GitHub Copilot, Perplexity, Grok, Mistral, NotebookLM and Glean are optional, and you can add your own domains.
  - All of `.cloud.microsoft` is opt-in, because most of Microsoft 365 uses it.
- **What it builds:**
  1. The AI Guard CA. Upload the `.pem` or pick the one already in ZIA.
  2. The proxy, `forward.prod.zsaiguard.net:9443` by default (`forward.zseclipse.net` also accepted), with X-Authenticated-User.
  3. A wildcard destination group of the AI app domains.
  4. A firewall rule that blocks QUIC, so the apps use TLS that ZIA can inspect.
  5. An **SSL Inspect rule at the top**, above every Do Not Decrypt rule including *Office 365 One Click*, so Microsoft 365 Copilot is inspected instead of bypassed.
  6. Gen AI prompt capture for the chosen apps, when licensed.
  7. A Proxy Chaining forwarding rule to the gateway.
- **Proxy gateways can't be created through the API.** The dry run shows the gateway as a *Manual step* with the exact portal settings. Run again once it exists and the forwarding rule is added.
- **Reuse:** if ZIA already has an AI Guard proxy and gateway, choosing its certificate reuses them instead of creating duplicates.
- **Follow-ups added to the POV:**
  - AI Guard portal settings: Store Prompts/Responses, ZIA user, group and domain sync.
  - WebSocket inspection for Copilot (Zscaler Support).
  - `NODE_EXTRA_CA_CERTS` for Claude Code.
- **Tests:** chain, Copilot inspection and QUIC are added to POV Tests.
- **Restore:** undo removes every AI Guard object.

### Active POVs (new in 2.4)
Run several POVs side by side, and come back to any of them exactly where you left off.
- **Sidebar › Active POVs** lists every POV with its customer, status (Planning → Built → Testing → Wrapping up → Closed), the step you left off at and when it was last touched. A POV with no activity for 7 days is flagged *quiet*.
- **POV home** has four tabs:
  - **Overview:** the POV plan (products, preset, baseline, domain, and what each product step is set up with), where things stand, next steps and the latest note.
  - **What the tool did:** every apply with its object ledger, restore points and the drift check.
  - **Tests & success criteria:** the customer-agreed criteria, each Met / Not met / Pending and linked to the tests that prove it, plus the runbook results.
  - **Timeline & notes:** kickoff, check-ins and end date, follow-ups (the wizard adds its own, e.g. move the App Connector Group out of San Jose), and dated notes.
- **Resume** reopens the guided flow at the exact step, with every choice restored, including edited ZPA applications, Client Connector settings, ZIA rule choices and ZDX apps. Progress saves automatically while you work.
- **The tenant guard:**
  - A POV remembers only its tenant's vanity domain and cloud.
  - Choosing a POV while signed out pre-fills the sign-in for that tenant.
  - A POV refuses to open when you're signed in to a different tenant, so nothing is written to the wrong customer.
- **Nothing secret is saved:**
  - No API credentials, provisioning keys, tamper or one-time passwords, or tokens.
  - A resumed POV gets a fresh Client Connector tamper password, and says so.
- **Saved templates:** *Save as template* keeps a POV's choices but never the customer, tenant, prefix, host names or secrets. Start a new POV from a template under *Active POVs › Templates*.
- **Export / import** a POV as one file. **Archive** removes it from the list; the folder is kept.
- **Where it's stored:** POVs live in `ZTP-Wizard/povs/` in your home folder (standalone builds) or in `povs/` next to the server install, and templates in `pov-templates/`.

### Guided POV (POV Start, the first page after sign-in)
The page shows one step at a time, with a progress bar of numbered steps at the top. Steps for products that aren't in scope are left out, and earlier steps keep what you entered.
1. **Tenant readiness:** read-only checks run before the customer sees anything.
   - **ZIA:** pending changes, SSL rules placed above *Zscaler Recommended Exemptions*, isolation profiles, the Trusted Resolver and identity-provider groups.
   - **ZPA:** App Connectors online, PRA portal, web certificates and isolation profiles.
   - **Client Connector:** enrolled devices.
   - **ZDX:** reachability.
   - **Licensing across the whole tenant:**
     - A missing core licence is a caution: URL Filtering, Cloud App Control, SSL Inspection, ATP, Antivirus, Sandbox, web DLP, Firewall, DNS Security, Client Connector or Browser Isolation.
     - Optional licences are info.
     - Trials ending within 21 days and missing ZPA AppProtection or PRA are also flagged.
2. **Build the POV:** choose Internet Access, Private Access and/or Digital Experience. Client Connector is added whenever Internet Access or Private Access is in scope.
3. **Customer intake:**
   - Customer name.
   - Prefix, generated from the name and editable. It names every object the wizard creates.
   - Internal domain, saved for ZPA.
   - Preset: Healthcare, Financial services, General enterprise, Education or empty.
   - Baseline policies.
4. **Client Connector:** forwarding and app profiles for Windows, macOS or both, or skip.
5. **Internet Access:** scope → baseline (preselected from the intake) → rules, with every toggle.
6. **Private Access:** the ZPA wizard, pre-filled from the preset. Every application's name, destinations and TCP / UDP ports are editable, and **+ Add application** adds rows by hand.
7. **Digital Experience:** probes pre-filled with apps for the market segment.
8. **Dry run & apply:** one dry run covers everything. One apply follows, with live progress. Each product has an *Edit* button that goes back to its step.

**Presets.** Every preset includes ZPA segments for:
- a `*.<domain>` wildcard
- Active Directory, file shares, the intranet and an RDP jump host.

It also includes Outlook Online in ZDX, on top of the template's Microsoft Login, Teams, Zoom and Webex probes. Each preset then adds:

| Preset | Baseline | Own ZPA apps | Own ZDX apps |
|---|---|---|---|
| Healthcare | HIPAA | Epic Hyperspace / Interconnect, Imprivata, PACS, Cerner | UpToDate, Epic UserWeb, Doximity, EHR web |
| Financial services | PCI DSS | Core banking, trading platform | Bloomberg, Workday, DocuSign |
| General enterprise | Balanced | — | Salesforce, Workday, DocuSign |
| Education | Balanced | Student information system | Canvas, Google Classroom, PowerSchool |

### Safe by design
- **Every change goes through a dry run first.** The preview shows Create / Update / No change for each object, with old → new values for every changed field. The server refuses an apply that doesn't match its dry run.
- **No duplicates:** re-running with the same prefix updates objects in place.
- **ZIA changes are activated automatically.**
- **One failure never stops the rest:** each failure is listed with its reason, and anything that depends on it is skipped.
- **Restore & Drift:** every ZIA / ZPA apply saves a snapshot (no secrets).
  - *Restore* deletes what a run created and puts back what it updated.
  - *Drift check* lists anything changed since, with before / after values.
- **Client Connector / ZDX rate limits** (about 100 calls per hour) are counted and shown. When Zscaler asks the wizard to wait, a countdown appears and the step retries on its own.
- **Secrets:** provisioning keys and tamper passwords appear only on screen and in reports marked sensitive. One-time passwords appear only on screen. None of them is ever logged.

### Zscaler Internet Access
- **Baselines:**
  - Compliance frameworks: HIPAA, HITRUST, NIST 800-53, NIST 800-171, PCI DSS, CJIS, SOX, FERPA and GDPR, each with cited sources.
  - Or a level: Strict, Balanced, Permissive or Zero Trust Hospital.
- **Rule review:**
  - On / off for every rule.
  - Allow / Block all per category, Allow / Block per rule, and Isolate for URL rules.
  - Search, a *Changed from default* filter and keyboard shortcuts.
  - Selections can be saved and loaded.
- **Policy areas:**
  - Inline DLP Monitor or Block, with custom dictionaries and engines (ICD-10, MBI, MRN and more).
  - Endpoint DLP.
  - Cloud Sandbox Standard or Advanced, with AI Instant Verdict.
  - AI Prompt Capture (14 GenAI apps).
  - UCaaS, always enabled.
  - ATP defaults.
- **Granular Cloud App Control:**
  - Google Drive, Dropbox and Box: view-only.
  - Facebook and X: no posting.
  - LinkedIn: read-only.
  - ChatGPT, Gemini and Copilot: no file uploads.
  - Slack: no file uploads.
- **Templates** include:
  - The SSL inspect-remaining rule, always last and below *Zscaler Recommended Exemptions*, with TLS 1.2 minimum.
  - DNS over HTTPS inspected, with risky DoH lookups blocked.
  - All DNS answered by the Zscaler Trusted Resolver.
  - SSH / RDP / FTP dropped to and from high-risk countries.
  - Miscellaneous / Unknown sites opened in Browser Isolation.
- **Unlicensed features** are greyed out.

### Zscaler Client Connector
- **Profiles:** Windows and macOS forwarding and app profiles from the POV best-practice templates, with every setting a switch.
- **Tamper protection password:** one password protects logout, exit and uninstall, and turning off ZIA, ZPA or ZDX.
- **Bypass apps:** predefined IP bypass apps are read live from the tenant.
- **Lists:** VPN gateway, IP and DNS lists are validated before anything is sent.
- **Defaults:** ZPA reauthentication is on, and there are separate IPv6 switches.
- **Devices & Install:**
  - Enrolled devices, with one-time passwords per device.
  - The install builder from the Deployment Toolkit, covering every MSI / EXE / macOS parameter. It builds the command and a ready-to-run `.bat` or `.command` script.

### Zscaler Private Access
- **Objects created:** App Connector Group → Provisioning Key (masked, with reveal and copy) → Segment Group → Server Group → Application Segments, with the recommended defaults.
- **Applications:** one wildcard segment, preset apps, or a CSV upload of applications (`Application Name, Destinations, Ports`, with `;` between values and UDP ports as `udp:53`), with row-numbered validation and per-app settings.
- **Policies**, on by default:
  - access (everyone)
  - timeout (8 hours, or 1 hour idle)
  - AppProtection inspection (OWASP Core Rule Set)
  - browser isolation, with a POV isolation profile (copy / paste, upload / download, printing, watermark).
- **Optional:**
  - Browser Access, using a web certificate from the tenant.
  - Privileged Remote Access RDP / SSH consoles in the tenant's PRA portal.

### Zscaler Digital Experience
- **POV template:** Microsoft Login, Teams, Zoom, Webex and zscaler.com, each with a Web and a CloudPath probe.
- **Additional apps:** any predefined or custom app can be added.

### POV Tests and reporting
- **Runbook:** a test for every policy created, with Pass / Fail / Skip tracking. It downloads as Markdown and feeds the report.
- **Prove it:** for a URL, shows its categories and the URL rule that matches, plus Z-Insights totals.
- **DLP test kit:** synthetic PHI, card-network test cards and SSN files.
- **Summary report:** Markdown or printable HTML. It lists every object by product, decisions, warnings, follow-ups and test results, and is marked sensitive when it holds secrets.

### Interface
- **Light theme (2.5):** a green-on-white professional look is now the default. Dark mode is one click away (sun / moon toggle, remembered per browser).
- **About page (2.5):** what the tool does, who built it (Steven Hajny, Zscaler Distinguished Sales Engineer, [LinkedIn](https://www.linkedin.com/in/stevenzhajny)) and the version history. It is an independent project, not an official Zscaler product.
- **Icons (2.5):** clean line icons replace the emoji in the sidebar and on the product cards.
- **One Bulk Rule Manager** (above Policy Catalog) for ZIA, ZPA and ZDX. It deletes the wizard's objects in dependency order, after a preview.
- **The layout fits the window at any size:**
  - The content column fills the window.
  - Wide tables scroll inside their card.
  - Fields stack on narrow windows.
- **Update badge** when a newer version is on GitHub.

## Known limitations
- AI Guard proxy gateways can't be created through the ZIA API. The wizard shows the portal steps and picks the gateway up on the next run.
- Endpoint DLP rule creation hasn't been tested live, because the test tenant isn't licensed for it.
- The Client Connector and ZDX APIs allow about 100 calls per hour per API client.
- Zoom and Webex probes need the customer's account prefix; when it is left blank they are skipped with a note.
- Per-transaction logs can't be read with API client credentials, so *Prove it* points to Web Insights › Logs.
